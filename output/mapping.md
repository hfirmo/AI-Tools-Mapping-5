### Pricing sources & method (added v2.11)

The two pricing columns report **published list prices in USD per 1M tokens (input/output), standard tier** — they are not estimates, with one labeled exception. Source hierarchy: (1) vendor first-party documentation, (2) independent pricing trackers with visible sync dates, (3) recent editorial roundups; load-bearing numbers cross-checked where possible. Cell-level provenance: **Claude** — Anthropic's platform pricing docs, corroborated by same-week trackers (strongest sourcing in the column). **Grok** — tracker reading xAI's official docs. **OpenAI tiers** — current roundup, Sol output rate independently corroborated. **Gemini 3.1 Pro ($2/$12)** and **Qwen 3.7 Max** — single non-first-party source each; treat as provisional. **Cohere** — pre-2026 training-knowledge rate, labeled. **DeepSeek** — the one extrapolation: projected from pre-2026 rates, no verified V4 card found; hence "verify."

Exclusions: cache pricing, long-context surcharges, gateway/reseller rates, regional and enterprise pricing — list price ≠ effective price. Tokenizer caveat: vendors tokenize differently and tokenizers change between model generations (documented shifts of up to ~35% more tokens for identical text), so per-token price does not equal per-text cost; for corpus budgeting, measure dollars-per-interview empirically on a sample. Promotional rates (Sonnet 5 intro; Qwen promo) are time-bounded as noted.

### Why this table is vendor-level, not model-level (added v2.12)

Benchmark trackers currently measure ~576 models, of which ~150 are fully evaluated on a comparable index. That count is not a target for this table, for four reasons. (1) **Unit mismatch**: most of those entries are configurations of the same model (reasoning-effort variants, fallback settings), historical versions, or non-text models (image, video, speech) irrelevant to text QDA. (2) **Column mismatch**: every row here carries human judgments — contribution to QDA, strengths, limitations, lower/higher-order tag — which are written per *positioned interlocutor*, not per checkpoint; a per-model version would be a leaderboard, not a mapping, reverting the framework's own move from cataloguing tools to mapping epistemic configurations. (3) **Licensing**: benchmark datasets belong to their publishers; this document links and cites them rather than reproducing their tables. (4) **Maintainability**: hand-written judgments at that scale cannot be kept current.

Comprehensive coverage is instead handled as an **appendix**: `scripts/model_index.py` in the companion repository auto-populates a "Model index (auto)" sheet from an openly licensed, machine-readable price map (provider, model key, input/output price, context window), filtered to text models. Curated judgment stays in Table 1; exhaustive enumeration lives in the appendix; benchmark *quality* rankings stay where they are maintained — cite Artificial Analysis (https://artificialanalysis.ai/models) as a live source rather than copying it.

## Table 2. Build-your-own option (Llama / Ollama ladder)

| Level | What you build | Skills / effort | Best suited for |
|---|---|---|---|
| 1 | Local model via Ollama or LM Studio; codebook in system prompt | None; an afternoon | Private exploratory analysis of sensitive transcripts |
| 2 | + Retrieval (RAG) via Open WebUI / AnythingLLM over full corpus | None; point-and-click | Private NotebookLM-equivalent: grounded corpus Q&A |
| 3 | Batch coding pipeline via Ollama's local API; structured JSON outputs; logged prompts | Basic Python — or AI-written Python supervised through Cursor / Claude Code; feasible for non-programmers who commit to understanding the code | Reproducible deductive coding at scale; validation vs. human coders (e.g., Cohen's kappa) |
| 4 | QLoRA fine-tune on your own coded excerpts (Unsloth / Axolotl) | ML skills; hundreds of labeled examples; consumer GPU (AI editors lower the scripting barrier; comprehension still required) | High-volume consistent deductive coding; usually unnecessary — good prompting + RAG often suffices |

**Key trade-off:** self-hosting maximizes ethics (data never leaves your machine), reproducibility (pinned model versions), and cost control at scale — but the capability gap vs. frontier models is largest exactly on higher-order interpretive work. **Common hybrid:** local model for anything touching raw participant data; frontier model for theorizing over anonymized summaries.

**Builder-layer note (v2):** an AI coding editor changes the economics of Levels 3–4: the researcher describes each pipeline component in plain language and supervises AI-drafted code instead of writing it. Two disciplines keep this defensible: (1) the *explain-every-line rule* — no component runs until the researcher can account for what it does, since a silent retrieval or parsing bug shapes which excerpts are ever seen (an invisible validity threat); (2) *instrument provenance* — builder sessions are logged like any other human–AI interaction, because an AI-co-written instrument is part of the study's construction. Keep the corpus outside the editor's workspace: AI editors index and transmit workspace files, so code and data must live in separate folders.

## Overall pattern

Nearly all current tools cluster at the **lower-order** end (retrieval, organization, coding). **Higher-order** analysis — abstraction, multiple reasonings, problematization — is reached today mainly through (a) dialogic use of frontier LLMs with the human retaining interpretive authority, (b) pattern-discovery tools that surface the unexpected, and (c) literature-graph tools that enable cross-field connections. The field's consensus: researchers want full agency over inductive interpretation; AI assists, humans theorize.

A v2 addendum: one further category interprets nothing yet shapes everything — the **builder layer** (Category H) constructs the apparatus through which all other layers operate. Its outputs are code, not readings; its epistemological significance is that AI involvement in a study can begin before the first transcript is touched, which is why instrument provenance belongs in the audit trail.

A v2.8 addendum: the Owner column reveals the ecosystem's governance structure at a glance — a handful of frontier labs and Big Tech firms (OpenAI, Anthropic, Google, Microsoft, Meta) anchor Categories A, B, and H–K; a belt of small commercial vendors owns the dedicated QDA and discovery layers; and a nonprofit/academic commons (Ai2, Cambia, OurResearch, Utrecht, Hugging Face, the open-source projects) quietly underwrites much of the infrastructure. Which firms own which layers is itself an analytic finding: the interpretive frontier is concentrated, while the commons carries the plumbing.
